# 写在前面 {.unnumbered}

Agent 技术真正困难的部分，不是学会调用某个 SDK，而是把概率模型嵌入一个可验证、可恢复、可授权、可运营的软件系统。对资深后端工程师而言，新的挑战不在于忘掉过去，而在于重新理解控制流：一部分控制权从确定性程序移交给模型以后，系统必须用工具契约、状态机、评测、权限和反馈重新建立边界。

本书沿三条线索展开：Agent 从哪里来，2026 年的工程系统处在什么阶段，以及未来哪些变化值得提前准备。它不会把产品功能表当作知识体系，也不会把“自主”当作默认目标。每一种模式都必须回答：为什么需要它、引入了什么新能力、产生了什么新故障，以及怎样证明它比更简单的方案更好。

当前版本是 v2 foundation 审核包，只包含两篇完整样章。它的目的不是营造“全书已经完成”的错觉，而是让读者和维护者先审核叙事深度、代码抽象、图表语言、引用方式和 PDF 阅读体验。审核通过后，余下章节才按相同标准展开。

::: {.chapter-synopsis}
**适合读者**：有多年后端、分布式系统、平台工程或技术管理经验，希望转型 Agent 工程、AI 平台或智能应用架构方向的工程师。

**不要求**：训练过基础模型或掌握复杂的深度学习推导。

**要求**：能阅读 Python/TypeScript，理解 API、状态、并发、权限、测试和生产运维。
:::
